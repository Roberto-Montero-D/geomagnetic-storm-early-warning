## 1. Purpose

v2.0 is a new experiment motivated by the completed v1.3 Final Test and its explicitly post-hoc Phase 9 diagnostics.

It does **not** repair or reinterpret v1.3.

The central question remains operational:

> Can a causally valid system warn that geomagnetic storm conditions associated with a new canonical storm event will occur within the next six hours while maintaining an acceptable false-alarm burden across changing geomagnetic regimes?

The successor study focuses on two limitations exposed by v1.3:

1. poor event recall when canonical events occur during already disturbed/recurrent conditions;
2. temporal/generalization instability, including the 2025 regime shift and failure of the development-selected false-alarm operating point to generalize.

## 4. Hypotheses Generated by v1.3 Phase 9

These hypotheses were generated after inspecting 2022–2025 and therefore are **development hypotheses**, not prior evidence.

### H1 — Background-relative state

Features representing current conditions relative to recent causal background may improve detection when absolute geomagnetic activity is already elevated.

### H2 — Recovery / recurrence state

Explicit causal indicators of recent geomagnetic activity and recovery state may help distinguish a new event from continuation or re-intensification.

### H3 — Target/evaluation alignment

An onset-window target may align more directly with event-level evaluation than the v1.3 future-condition target, particularly in recurrent/disturbed regimes.

### H4 — Regime robustness

A model selected for worst-fold operational robustness rather than average discrimination alone may generalize more reliably across activity regimes.

### H5 — Calibration / operating-point stability

Time-aware probability calibration may reduce the failure of a development-selected threshold to maintain its intended false-alarm rate prospectively.

No hypothesis is assumed true before development testing.

## 5. Target Experiments

Two target formulations are proposed and must be frozen before screening.

### Target A — Condition-in-window control

This reproduces the v1.3 prediction target:

```text
y_condition(t) = 1 if max(Kp in (t, t+H]) >= T
```

Purpose: continuity control.

### Target B — Canonical onset-in-window

```text
y_onset(t) = 1 if a canonical storm start occurs in (t, t+H]
```

Purpose: directly align training labels with event-onset warning.

Rules:

- canonical events use the same frozen `T` and `Z` semantics;
- target construction is retrospective truth only;
- no future event information may enter predictors;
- prediction rows during an existing storm remain valid rows; their onset target is positive only if a new independent canonical start lies in the future window;
- Target B must not redefine event truth after seeing development results.

Target choice for the final v2.0 system is made **only from development folds** using the ranking rule in Section 10.

## 6. Predictor Families

All candidate features must be causal at prediction time.

### F0 — v1.3 control

The frozen v1.3 10-feature raw family.

Purpose: direct development benchmark.

### F1 — Causal background-relative state

F0 plus predeclared background-relative variables derived only from past observations, including candidates such as:

- current Bz minus trailing 12 h and 24 h median Bz;
- current Bt minus trailing background Bt;
- current speed minus trailing 12 h and 24 h median speed;
- current pressure minus trailing background pressure;
- current coupling (`Bz_neg * speed`) minus trailing coupling baseline;
- causal Kp minus trailing 12 h / 24 h median Kp;
- short-minus-long rolling differences for selected physical variables.

All windows must exclude information newer than the source-specific information cutoff.

### F2 — Recovery / recurrence state

F1 plus predeclared causal geomagnetic-state variables, such as:

- active Kp hours in prior 6/12/24 h;
- median/max causal Kp in prior 6/12/24 h;
- hours since most recent observed `Kp >= T` interval;
- consecutive hours below `T` since the most recent observed active interval;
- causal recent-disturbance flag;
- recovery-duration state;
- speed persistence above fixed physical thresholds;
- southward-Bz persistence below fixed thresholds.

These features use **observed historical state only**. They may not use future-completed canonical event identities.

### F3 — Transition / dynamics state

F2 plus a small frozen set of already-causal dynamics/interactions:

- Bz deltas/slopes;
- speed deltas/slopes;
- pressure deltas/slopes;
- southward-Bz × speed coupling;
- selected change-from-background interactions.

No automated feature-mining procedure is authorized unless added before protocol freeze.

### Solar/CME predictors

CME-derived variables remain excluded from the primary v2.0 feature set unless their real-time availability semantics are reconstructed and independently tested before protocol freeze.

## 9. Candidate Models and Calibration

The candidate set should remain intentionally small.

### Primary model candidates

Proposed:

- Logistic Regression;
- ExtraTrees;
- LightGBM;
- XGBoost.

Hyperparameter grids must be frozen before screening and should be narrower than broad exploratory searches.

### Imbalance handling

Primary proposal:

- no resampling;
- optional fixed class-weight candidates only, frozen before screening.

Synthetic oversampling is not a priority hypothesis for v2.0 because v1.3 failure analysis implicated regime/context and operating-point drift more strongly than lack of minority examples.

### Calibration candidates

Proposed time-aware candidates:

- none;
- Platt/logistic calibration;
- isotonic calibration, only if fold sample support is sufficient.

Calibration must be trained using development predictions without using the same validation labels both to fit calibration and to report its performance. Nested or cross-fitted calibration is required.

## 10. Development Selection Rule

Selection is operational and lexicographic.

### 10.1 Feasibility

For each candidate, generate temporally valid out-of-fold predictions and select an operational threshold from development only.

A candidate is operationally feasible when pooled development OOF:

```text
FAR/day <= 0.20
```

In addition, report fold-level FAR/day and threshold stability.

### 10.2 Ranking among feasible candidates

Proposed ranking order:

1. highest **worst-fold Event Recall**;
2. highest median fold Event Recall;
3. highest mean PR-AUC;
4. lower fold-to-fold FAR/day variability;
5. better calibration/Brier score;
6. simpler feature/model configuration as tie-breaker.

This ranking intentionally emphasizes temporal robustness.

### 10.3 Regime stress diagnostics

For development reporting only, each candidate must report Event Recall in predeclared causal context strata, including:

- quiet-background;
- active-background;
- recent-disturbance/recovery state.

These diagnostics may break ties only if explicitly authorized before freeze. Otherwise they are descriptive.

---

## 11. Threshold Selection

The final operational threshold must be selected once from pooled development-only OOF predictions after target/feature/model/calibration selection.

Primary threshold rule:

> Select the lowest threshold satisfying pooled `FAR/day <= 0.20`.

Required diagnostics:

- global threshold;
- fold-specific feasible thresholds;
- FAR/day by fold at the global threshold;
- Event Recall by fold at the global threshold;
- threshold stability range;
- calibration curve/Brier score by fold and time period.

The threshold is then frozen before any protected Final Test outcome access.

## 12. Predeclared v2.0 Success Criteria

The protected Final Test remains the decisive evaluation.

Proposed primary success requirements:

```text
FAR/day <= 0.20
Event Recall >= 0.60
median early lead time >= 3 h
```

All three must be reported independently; no weighted composite may hide failure of the FAR constraint.

Secondary metrics:

- PR-AUC;
- ROC-AUC;
- Brier score;
- calibration/reliability;
- alert episodes;
- false-alarm episodes;
- lead-time distribution;
- annual metrics;
- predeclared causal regime-stratum metrics.

Failure to satisfy a primary criterion is reported as failure, not repaired post hoc.

## 17. Current Draft Position

The intended v2.0 strategy is deliberately not “try more models.”

It tests whether the successor system becomes more robust by explicitly representing causal background/recovery state, aligning the prediction target more closely with new event onset, selecting for worst-period operational performance, and controlling calibration/threshold stability.

These ideas came from the consumed v1.3 Final Test and are therefore legitimate **development hypotheses only**.
